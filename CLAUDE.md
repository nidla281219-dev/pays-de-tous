## Règles de l'utilisateur
- ZONE VISIBLE : texte et éléments importants dans x 60–960, y 130–1600 ; ligne ≤ 840 px (centre x ≈ 510). Vérifier avec --cadre.
- 2 à 3 questions MAX par vidéo. Vidéo ≤ 45 s (≤ 52 s avec acheteurs), voir PLAN ANTI-BAISSE. Couper les récaps.
- PLAN ANTI-BAISSE (19.11, stats jour 12 : TikTok 6 s de moyenne, la plupart partent à 0:01 ; vidéos de 61–71 s malgré la règle ; 0 partage) — PRIORITAIRE :
  a) DURÉE STRICTE : script ≤ 95 mots (≈ 35 s) hors merci acheteurs ; vérifier avec `wc -w` avant d'envoyer le script, couper sinon. Vidéo finale ≤ 45 s (≤ 52 s avec acheteurs). Plus de chiffres par réseau, plus de récap d'hier.
  b) POUR LES NOUVEAUX : 99 % des vues viennent de gens qui ne connaissent pas la série. Les 3 premières secondes = le CONCEPT + l'enjeu, compréhensibles sans avoir vu avant. Modèle : « 2 000 inconnus dirigent ce pays avec leurs commentaires… et ils viennent de piéger un roi. » (la vidéo à 34 k vues = « hier on était zéro, aujourd'hui 233 »). Jamais de « leur roi », « l'ennemi », « la guerre » sans contexte.
  c) IMAGE 1 : claire, de jour ou très éclairée, en mouvement, gros plan (perso, foule, explosion), JAMAIS « JOUR N » écrit sur l'image 1 (le mettre dans le HUD seulement, après 3 s). Texte image 1 = l'enjeu en 3–5 mots.
  d) UNE SEULE question à la fin, simple (A ou B) + raison de partager.
  e) Merci acheteurs + pub : courts et APRÈS la question ; la pub longue va en story/carrousel, pas dans la vidéo.
- GIGA ACCROCHE (17.11, stats IG : 50 % partent avant 4 s, 0 partage, < 10 % à la fin) : charger le skill `viral-hooks` à l'étape 3, écrire 6 accroches (≥ 3 archétypes : conflit/danger, retournement, gros chiffre, question piège, « avant/après », mystère), garder la meilleure et mettre les 2 suivantes dans le message à l'utilisateur. Règles : JAMAIS commencer par « Jour N » (le dire après 3 s) ; événement montré dès l'image 1 (feu, bateau ennemi, foule, statue géante, gros plan) + 3–5 mots ÉNORMES + phrase dite < 2 s, tout aligné (dit = montré = écrit) ; être créatif mais tenir la promesse dans la vidéo. Relances toutes les ~10 s (« mais… », « sauf que… »).
- PARTAGE : une raison concrète d'envoyer la vidéo (« Envoie-la à un pote : s'il s'abonne, il devient habitant et vote avec toi », camps rivaux, « tag celui qui serait chef »). Finir sur un SUSPENSE (une question ouverte ou une menace pour demain), pas sur « Demain, jour N+1 » seul.
- ACHETEURS + PUB À CHAQUE VIDÉO : 1) remercier chaque nouvel acheteur (ventes.yml → vitrines.py, règle MAISONS PAYÉES) ; 2) une pub courte (≤ 5 s) pour les maisons : « Toi aussi, ta maison dans les Hauts, lien en bio — tout reste gratuit, ça finance notre jeu Vulkaris. » Placée APRÈS l'accroche et le vote, jamais au début.
- CONSTRUIRE CE QUE LES GENS DEMANDENT, avec le NOM de la personne sur le bâtiment, dit à voix haute. Bâtiments BEAUX et détaillés (jamais des boîtes).
- Habitants visibles quand la voix annonce leur nombre.
- Trésor : 1 like = 1 pièce (likes des 3 vidéos) ; toujours inciter à liker.
- Chiffres TOUS RÉSEAUX CONFONDUS (« au total », « sur tous les réseaux ») mais NE JAMAIS NOMMER une plateforme (vidéo, descriptions, épinglés).
- Vote : compter le NOMBRE de personnes qui proposent la même chose, plus les likes. Chef = candidature la plus likée.
- MAISONS PAYÉES (13.11, l'utilisateur insiste : « c'est cher payé pour apparaître à la va-vite ») : chaque acheteur a SON moment, ≥ 4–5 s par maison (≥ 2 plans : un plan large qui tourne lentement autour de la maison + un gros plan sur le panneau à son nom), carte « ⭐ Merci <pseudo> » + phrase dite à voix haute avec le type de maison et ses options. Modélisation TRÈS SOIGNÉE, identique à l'aperçu du site (reprendre maison(), terrain(), opts(), statue(), panneauNom() de boutique/index.html : mêmes styles, couleurs, options, statue), jamais une boîte simplifiée. Feu d'artifice à l'écran si l'option « feu » est achetée. Vérifier chaque maison en 2 images test avant le rendu. S'il y a beaucoup d'acheteurs, garder ≥ 4 s chacun quitte à allonger un peu la vidéo. OUTIL OBLIGATOIRE (14.11, l'utilisateur : caméras derrière les maisons, textures qui vibrent, pas comme commandé) : `python3 studio/vitrines.py N pseudo1 pseudo2…` → jours/jourN/maison_<pseudo>.mp4 (~7–8 s : orbite DEVANT la maison + gros plan panneau + statue si achetée, carte MERCI pseudo, description de la commande, feu d'artifice si acheté), rendu avec le code EXACT du site → identique à la commande. L'insérer avec `inserts` (docs/TIMELINE.md) au moment où la voix remercie l'acheteur. Ne plus modéliser les maisons achetées dans scene.html. Regarder 3 images de chaque clip.
- Pas de voix chuchotée. Secrets uniquement dans GitHub, jamais dans le dépôt ni le chat. Ne jamais scraper avec le compte de l'utilisateur.

## Procédure quotidienne (tâche programmée 14h45, publication 17h00) — ÉCONOMISER LES TOKENS
Ne pas lire les gros fichiers (commentaires_*.json, scene.html, mots.json en entier) : utiliser les scripts et grep.
PARTIE 1
1. N = etat.jour + 1. Lancer commentaires.yml (jour N-1) ; attendre avec UNE seule commande en arrière-plan (pas de vérifications répétées) ; git pull.
2. `python3 studio/compter.py N-1 --opt "A=mots|…" "B=mots|…"` → chiffres par réseau + total, votes, propositions répétées, top commentaires. Lire commentaires_autres.txt s'il existe. Décider (banque_questions.md), mettre à jour etat.json (+ historique court).
3. Écrire jours/jourN/script.md (1re ligne « # titre » ; 40–50 s) : GIGA ACCROCHE (voir règles), puis « Jour N », ce qui a changé, merci aux gagnants (pseudo), construction, nouvelle(s) question(s), « Commente… », « Like = pièce pour le trésor », « Abonne-toi pour devenir habitant », raison de PARTAGER, pub maisons + merci acheteurs, SUSPENSE final. Commit/push.
4. Envoyer à l'utilisateur (court) : chiffres, gagnants, ce qui sera construit, trésor, questions, SCRIPT COMPLET, « Réponds OK pour lancer la vidéo ». ATTENDRE son OK. Sans OK : rien fabriquer.
PARTIE 2 (après OK)
5. Lancer voix.yml (jour N), attendre, git pull. Nouveau bâtiment : le modéliser dans scene.html (comme boulangerie()/universite()). Écrire timeline.json (docs/TIMELINE.md ; partir du timeline de la veille) calé sur mots.json (lire avec un petit script : mot + temps). Rendre et REGARDER seulement 3–4 images test : `cd studio && node render.js --jour N t/f --test a,b,c --cadre`.
6. Miniatures : `node render.js --jour N t/m --test <t> --propre` puis `python3 miniature.py t/m_<t>.jpg ../jours/jourN/miniature_youtube.jpg --style youtube "JOUR N" "*MOT*" "…"` (+ copie miniature.jpg) et `--style tiktok` → miniature_tiktok.jpg. Regarder chaque miniature une fois.
7. publication.json (YouTube : titre ≤ 100 car. « … Jour N : … », description, tags) + publication.md (YouTube / TikTok / Instagram, 3 hashtags max, un commentaire à épingler par réseau). HASHTAGS QUI CHANGENT (17.11) : #LePaysDeTous fixe + 2 liés au SUJET du jour, jamais les mêmes 2 jours de suite (ex. #guerre #pirates #île #ville #construction #élection #animation3d #jeuvidéo #simulation #royaume #trésor) ; plus de #pays #vote systématiques. CRÉDITS : gagnant du même réseau → @pseudo ; d'un autre réseau → pseudo sans @ et sans nommer le réseau.
8. Commit/push, lancer publier_rapide.yml (jour N, heure 17:00 ; 6 morceaux en parallèle, ~20 min). Attendre avec UNE commande en arrière-plan. (publier.yml = ancien rendu en un seul morceau, ~1 h, secours.)
9. git pull, envoyer ICI : jours/jourN/video.mp4 + les 2 miniatures, puis les textes prêts à copier. Ajouter 1 ligne à docs/JOURNAL.md.
10. RÉCAP EN CARROUSEL (demande de l'utilisateur, 13.11 : plusieurs images, très visuel) : rendre 6–9 images --propre des plus beaux plans (`node render.js --jour N t/c --test t1,t2,… --propre`), les copier dans jours/jourN/img_<t>.jpg, écrire jours/jourN/recap.json avec "slides" (modèle : jours/jour6/recap.json — 1 diapo = 1 image plein cadre + titre court : couverture JOUR N + habitants, décision d'hier, chef/commandant, chaque construction avec le pseudo, nouveaux habitants des Hauts = acheteurs, dernière diapo = vote du jour + trésor), puis `python3 studio/recap_carrousel.py N` → jours/jourN/carrousel/01.jpg… (1080×1440). Les regarder (planche), les envoyer ICI avec une légende courte (3 hashtags max, aucune plateforme nommée). (studio/recap.py = ancienne version 1 image, en secours.)
Si une étape échoue : réparer, sinon prévenir clairement (jamais de vidéo cassée publiée). La miniature YouTube peut être refusée (403) tant que la chaîne n'est pas vérifiée : il la met à la main.
